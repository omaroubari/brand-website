## Usage

Supply terms and values in the order readers should encounter them.

```mdx
<SpecList
  items={[
    { term: "Format", value: "SVG" },
    { term: "Use", value: "Digital artwork" },
  ]}
/>
```

Keep structured brand specifications in configuration and read them from
`props.brand` when they describe configured assets or tokens.

## Examples

### Keep longer values in stacked rows

The default layout keeps each term beside its value and stacks the pairs.
Use this for explanations that need more room than compact metadata.

<ComponentPreview path="spec-list" code={previewCode} />

### Place short specifications side by side

Use `inline` for a small set of compact values. Each term sits above its value.
This layout does not wrap or switch back to rows at smaller widths, so prefer
the stacked default for long values or many items.
