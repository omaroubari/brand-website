## How components receive your brand

Brandtree makes the 28 components in this reference available by name in content MDX. You do not need to import them. The generated route also passes the resolved, localized brand, interface strings, and content direction into the MDX document as `props.brand`, `props.ui`, and `props.dir`.

<Callout type="warning" title="Forward required props">

You must forward these values to each component that needs them. Making a component name available does not bind its props. For example, `<Logo />` is incomplete; use `<Logo brand={props.brand} />`. Use the same forwarding inside any custom wrapper so translated content and interface labels stay aligned.

</Callout>

```mdx
<ColorPalette brand={props.brand} ui={props.ui} />
<Glyphs ui={props.ui} dir={props.dir} />
```

All component examples belong in a Brandtree content `.mdx` file. Import statements go after YAML frontmatter. Strings use quotes; numbers, booleans, objects, and arrays use braces. A self-closing component has no children; a paired component wraps prose or other components. Leave blank lines around Markdown inside paired tags so paragraphs and lists are parsed correctly. See [Pages and MDX](/authoring) for complete page examples and [Astro's MDX guide](https://docs.astro.build/en/guides/integrations-guide/mdx/) for the underlying syntax.

Props listed as **required** have no default. All components accept an optional `class` string except `ColorSwatch`. A `class` adds a hook to the outer element; it does not add arbitrary HTML props or inline styles to the public API.

Component selectors refer to configured IDs, not display labels, unless explicitly stated. Use [Configuration](/configuration) to define brand data, and [Media](/media) for image imports, SVGs, and downloadable files.

## Custom components and layouts

See [Custom components](/customization) for custom components and prop forwarding, and [Styling and tokens](/styling) for CSS, local scrolling, and theme support. Keep structured brand facts in configuration and editorial explanations in MDX.

`CoverPage` and `SectionOpener` are internal layout components, not built-in MDX names. The generated runtime owns the site shell, navigation, theme controls, and cover composition. Do not add application routes or edit generated `.brandtree/` files to use the authoring components.

<Panel title="Documentation components and Brandtree components">

This documentation uses Blume components for cards, steps, and reference tables.
The catalog above documents Brandtree components used inside your brand site.
Their APIs differ: Brandtree's `Callout` takes `tone` and `ui`, while Blume's
documentation callouts take `type`. Copy the catalog's MDX examples into your
