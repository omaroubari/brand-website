Frontmatter is the YAML block between `---` fences at the very beginning of a
file. It describes the page rather than its prose. All fields are optional;
explicit titles and descriptions make the result easier to maintain.

```yaml
---
title: Logo clearspace
description: The protected area around our logo.
slug: protected-area
draft: false
hidden: false
icon: ph:bounding-box
noindex: false
sidebar:
  label: Clearspace
  icon: ph:ruler
  badge: Updated
  hidden: false
seo:
  title: Logo clearspace guidelines
  description: Learn the minimum clearspace for our approved logo artwork.
  canonical: https://brand.example.com/logo/protected-area
  image: /images/logo-social.png
  noindex: false
---
```

The schema is strict: unknown fields cause a validation error. For example,
Brandtree does **not** accept `sidebar.order`, `layout`, `date`, `tags`, or
arbitrary custom metadata. This documentation app's `sidebar.order` belongs to
its Blume host. For a Brandtree site, use numeric filenames or folder metadata
as described in [Navigation](/navigation).

Setting top-level `hidden: true` or `noindex: true` takes effect even if the
corresponding nested value is `false`. Hidden and noindex pages are still public
URLs; neither setting provides access control.
