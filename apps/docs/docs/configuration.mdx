title: Configuration

---

`brandtree.config.ts` is the single source of structured brand data and site
settings. Use `defineConfig` from `brandtree` for editor completion; the CLI
validates values when it loads the project. Unknown fields are rejected.

For a guided setup, start with [Brand configuration](/brand-configuration).
This page follows the config object's structure so you can find a field quickly.

## Define and validate your config

This is the shape of a config file, **not a complete runnable configuration**.
Keep the required brand sections from the [Quickstart](/quickstart) starter.

```ts title="brandtree.config.ts — structure only"
import { defineConfig } from "brandtree";

export default defineConfig({
  brand: {
    // Required: meta, colors, theme, typography, logo, and contact.
  },
  navigation: { numbering: true },
});
```

The loader recognizes `brandtree.config.ts`, `.mts`, `.js`, `.mjs`, and `.cjs`,
in that order. Keep one config file. A config-free project does not currently
provide a complete brand automatically.

## Color families and swatches

`brand.colors.palette` contains families with required `id`, `name`, and
`shades`. Each `shades` object must contain all eleven stops: `50`, `100`, `200`,
`300`, `400`, `500`, `600`, `700`, `800`, `900`, and `950`.

A shade uses `{ space: "hex", value: "#64748b" }` or
`{ space: "oklch", l: 0.55, c: 0.12, h: 250, alpha: 1 }`. For OKLCH, `alpha` is
optional, lightness uses the 0–1 scale, and hue is in degrees.

Other color fields take references such as `slate-700`, `black`, or `white`.
`black` and `white` are built in. Raw hex strings are not valid references.

## Light and dark themes

`brand.theme.default` is `"light"`, `"dark"`, or `"system"`. Both `light` and
`dark` require all of the following roles, each a color reference:

| Group               | Required roles                                                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Page                | `background`, `foreground`                                                                                                                               |
| Cards               | `card`, `cardForeground`                                                                                                                                 |
| Popovers            | `popover`, `popoverForeground`                                                                                                                           |
| Main actions        | `primary`, `primaryForeground`                                                                                                                           |
| Supporting surfaces | `secondary`, `secondaryForeground`, `muted`, `mutedForeground`                                                                                           |
| Accent              | `accent`, `accentForeground`                                                                                                                             |
| Destructive actions | `destructive`, `destructiveForeground`                                                                                                                   |
| Controls            | `border`, `input`, `ring`                                                                                                                                |
| Charts              | `chart1`, `chart2`, `chart3`, `chart4`, `chart5`                                                                                                         |
| Sidebar             | `sidebar`, `sidebarForeground`, `sidebarPrimary`, `sidebarPrimaryForeground`, `sidebarAccent`, `sidebarAccentForeground`, `sidebarBorder`, `sidebarRing` |

See [Themes](/themes) for how roles map to CSS variables and how to review both
schemes without relying on JavaScript.

## Typography specifications

`brand.typography` requires the CSS font-family stacks `display`, `text`, and
`mono`, plus `families`, `weights`, and `scale` arrays.

- Family entries require `id` (`"display"`, `"text"`, or `"mono"`) and `name`.
  Optional fields: `foundry`, `url`, `note`.
- Weight entries require `name` and numeric `weight`. Optional: `italic`.
  Weight numbers must be unique, including entries marked italic.
- Scale entries follow the table below.

## Load fonts

Root-level `fonts` is an array; it is separate from `brand.typography`.
When omitted, it declares Inter from Google with `"100 900"` weights, normal and
italic styles, and system fallbacks. Supplying an array replaces that default.

## Logo specifications

`brand.logo` requires `logotype`, `brandmark`, `clearspace`, `minSize`, and
`colorways`. Optional fields are `favicon` and `pronunciation`.

| Object                  | Required fields                                                     | Optional fields |
| ----------------------- | ------------------------------------------------------------------- | --------------- |
| `logotype`, `brandmark` | `onLight`, `onDark` (file paths); `aspect` (numeric width / height) | `altText`       |
| `clearspace`            | `unit` (description), `ratio` (number)                              | —               |
| `minSize`               | `digital`, `print` (descriptive strings)                            | —               |
| Each `colorways` entry  | Unique `id`, `fg`, `bg` (color references)                          | `label`         |

The generated site otherwise references `/favicon.svg`. Keep the preferred
colorway first. See [Logos](/logos) for an example with artwork paths.

## Contact and downloads

`brand.contact` is required, but `{}` is allowed. Its optional fields are
`email`, `website`, `phone`, `address` (string array), and `socials`.
Each social entry requires a unique `id` plus `label`, `handle`, and `url`.
See [Contact and social profiles](/contact).

`brand.downloads` is optional. Entries require unique `id`, `label`, and `href`;
`format`, `size`, and `note` are optional display strings. Brandtree does not
create archives or calculate file sizes. See [Brand assets](/brand-assets).

## Localized brand copy

`brand.localeOverrides` is an optional record keyed by locale code. It requires
root `i18n`, and each key must be configured in `i18n.locales`.

Supported overrides are reader-facing metadata, palette names, swatch names and
usage, typography stacks and labels, logo text, address lines, social labels,
and download labels and notes. Array entries match canonical `id` values;
weight entries match their numeric `weight`. Unknown and duplicate identifiers
are invalid. Artwork paths, colors, URLs, measurements, and theme roles stay
canonical. See [Localization](/localization) for the complete workflow.

## Check your changes

Config validation checks unknown fields, duplicate IDs and weights, complete
schemes, color references, font variables, and locale references. It also reports
local asset warnings. See [Validation](/validation) for the checking workflow.
Visual review still matters for contrast, artwork, and typography.
