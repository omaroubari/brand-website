Start with the complete config in the example site, replace its values, and
keep required sections intact. The [configuration reference](/configuration)
lists the supported fields.

## Connect the config to your pages

A config describes the brand; an MDX page explains its use. Add a component to
show that shared data within your explanation:

```mdx
## Approved colors

Use the primary palette for our most recognizable applications.

<ColorPalette category="primary" />
```

The runtime supplies the resolved brand, interface strings, and direction for
the active locale to built-in MDX components automatically. Pass an explicit
prop to override a value for one component. See [Components](/components) for
examples, previews, and prop definitions.

<Panel title="Some tasks cross config sections">

Fonts are registered at `config.fonts` and referenced by `brand.typography`.
Brand translations live at `brand.localeOverrides` and require root `i18n`
settings. [Localization](/localization) walks through both together.
[Social cards and SEO](/social-cards) explains how generated cards inherit brand
values and where to override them.

</Panel>

<Callout type="tip" title="Keep editorial guidance in your pages">

Voice, values, photography direction, iconography, and layout principles are
written in MDX with the relevant components. They do not have dedicated fields
in the current brand schema. Start with [Pages and MDX](/authoring).

</Callout>
